# AGENTS.md — правила для агентів у `4wp-social`

Робоча директорія: `/Users/admin/Projects/4wpdev/4wp-social`. Стиль — як у `4wp-mcp-connector`.

## Спілкування з автором

- Українською, на «ви». Коротко, чітко, без повторів — автор читає все.
- Лише те, що просять. Не вигадувати. Неперевірене позначати **(уточнити)**.
- Не поспішати: спершу перевірити (код, документацію платформи), потім стверджувати.
- Жорстка економія токенів. Усе, що потребує надмірних ресурсів (субагенти, масові читання, довгі пошуки, веб), — лише після узгодження. Без запитань заради запитань.
- План дій — завжди файлом у `docs/plans/`, не в чаті й не поза репозиторієм.

## Зміни лише з дозволу

- Редагувати, створювати чи переписувати файли — **лише** коли автор явно попросив цю зміну. Аналіз і пропозиції — без запису, доки не буде дозволу.
- Старт робіт — **лише** після окремого повідомлення автора з явним «виконайте». Перед цим агент дає перелік файлів, які створить / змінить / видалить, і команд, що змінюють систему (`composer`, `npm`, `mv`, `rm` тощо).
- Відповіді на запитання, «так» / «погоджуюсь» — **не дозвіл** на запис. Після них — лише відповідь і очікування.
- «Виконайте» діє тільки на погоджений перелік. Щось поза ним — знову перелік і нове «виконайте».
- Перед будь-якою зміною **прочитати актуальний файл з диска**, не покладатися на пам'ять чату.

## Git — ніколи

- `git commit`, `push`, гілки, теги, релізи агент **не робить ніколи**. Коміти робить автор.
- Агент лишає зміни в робочому дереві й наприкінці дає перелік змінених файлів.

## Також лише з дозволу автора

- Видалення файлів.
- Додавання залежностей (Composer, npm).
- Зміна рішень у `docs/decisions/` — нове рішення = новий ADR.
- Будь-які дії поза цією директорією (4wp-drive, 4wp-mcp-connector, тема 4wp.dev, хаб).
- Дії в зовнішніх сервісах (Meta, TikTok, Google консолі, публікації на платформах).

## Джерела істини (по порядку)

1. `docs/decisions/` — прийняті рішення.
2. `docs/SPEC.md`, `docs/ABILITIES.md`.
3. Офіційна документація API платформ (Meta Graph API, YouTube Data API, TikTok Content Posting API, AT Protocol, DEV.to). Версії й назви полів звіряти перед використанням.
4. `docs/CONCEPT.md` — бачення; якщо суперечить SPEC, діє SPEC.

## Робочий процес

1. Нова можливість або зміна рішення → ADR `docs/decisions/NNNN-назва.md` + рядок у `docs/decisions/README.md`.
2. План `docs/plans/<назва>.md`: кроки зі статусами, таблиця «файли → що», таблиця перевірок.
3. Перелік файлів → «виконайте» автора → код.
4. Перевірка: `php -l`, `composer lint`, `composer test`, ручна перевірка на `4wpdev.local`. Результати — у таблицю перевірок плану.
5. Оновити `docs/`, `README.md`, `readme.txt` (версія, changelog) у тому ж кроці.

## Код

- PHP 8.0+ (див. `composer.json`), WordPress Coding Standards, PHPCS (`phpcs.xml`, pre-commit: `git config core.hooksPath .githooks`).
- Namespace `ForWP\Social\`, код у `src/` (PSR-4), файли `Class_Name.php`, запасний `src/Autoload.php`.
- Text domain `4wp-social`. Префікс опцій, хуків, функцій: `forwp_social_*`; REST: `forwp-social/v1`.
- Нова платформа = `Platform_Adapter_Interface` (`src/Modules/Posting/Adapters/`) + клієнт у `src/Api/` + за потреби `OAuth_Provider_Interface` (`src/Auth/`). Зразок — `TikTok_Adapter`.
- Секрети — лише через `Credentials_Store` / `Token_Store` (`Crypto`). Жодних токенів у логах, документації чи чаті.
- Усі рядки інтерфейсу — через i18n-функції. Вивід — з escaping, ввід — з sanitizing, форми — з nonce.
